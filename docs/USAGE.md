# 操作・動作仕様

対象: `2026-10-22-stable-v2`。認識・再生の安全条件はベース版の仕様を維持します。

## Shazamの仮表示と確定

1回目の曲情報で仮行を追加し、YouTube検索とPRELOADを先行します。
コメント欄は `(仮)`、タイアップがあれば `(仮) タイアップ情報` となります。
2回一致が確認できない候補は自動再生しません。
確定し履歴へ反映されたらラベルを外し、実際のコメントだけを表示します。
曲情報待ちの間は `(確定・情報補完中)` と表示される場合があります。
これは歌ネットの待ち時間を示すものではなく、既存のShazam候補状態の表示です。

メタデータが届く前に2回の同一IDがそろっていると、仮追加と確定がほぼ同時になります。
この版では表示時間を人為的に延ばしていません。
ラベルは表示専用で、手動検索も自動検索も元の曲情報を使います。

## タイアップ補完

アニメOPモードの横のボタンでON/OFFを切り替えます。
歌ネットの取得はPythonのHTTPS通信で行い、追加のWebViewは使いません。
許諾確認の既存処理は維持しています。

| 結果 | 自動再生の対象 |
|---|---|
| OFF | 通常検索の結果 |
| ON、補完待ち | 通常検索・PRELOADは進め、PLAYは保留 |
| コメントあり | 補完後の検索結果のみ |
| 該当なし・空欄・取得失敗 | 通常検索の結果 |
| 補完成功、YouTube結果なし | 補完後検索 → 通常Shazam検索語 → アーティスト省略の順に再試行。全て0件なら自動PLAYなし |

どの経路も、自動再生ON・2回一致・動画準備完了が必要です。
補完失敗だけで曲を履歴から削除することはありません。
仮候補が2回一致せず別曲・期限切れ・No matchの上限で取り下げられる処理は別です。

補完時は通常検索を無効化し、その終了を待たずに補完後検索を開始します。
送信済み通信が内部で続く場合も、古い結果で新しい画面や再生を上書きしません。

## 検索テンプレート

設定画面のYouTubeタブで、Shazam通常検索と補完後検索を別々に設定できます。
既定値は `%tracktitle% %artist%` / `%tracktitle% %comment%`です。
コメントがないときの `%comment%` は空文字です。
**タイアップ補完後の検索（コメントあり）は最大3段階です。**

1. 補完後の設定値（初期値：`%tracktitle% %comment%`）
2. 0件なら通常Shazam検索の設定値（初期値：`%tracktitle% %artist%`）
3. まだ0件なら通常Shazam検索からアーティストを削除（初期値：`%tracktitle%`）

曲名 `Dolphin☆jet`、歌手 `彩音`、コメント `ケンコー全裸系水泳部 ウミショー オープニング` なら、
`Dolphin jet ケンコー全裸系水泳部 ウミショー オープニング` →
`Dolphin jet 彩音` → `Dolphin jet` です。`☆` を空白にする既存の正規化は変えていません。
通常検索テンプレートも設定された値を使用するため、カスタム設定では語順が変わります。
重複語を省略し、最大3検索で終了します。0件またはフィルターで全件除外の場合だけ進み、API／通信エラーでは進みません。

2・3段階目も、**補完後検索の新しい検索スレッドによる再試行**です。以前の通常検索の動画・PRELOAD通知を再度有効化するわけではなく、Shazamの2度一致とreadyが揃うまでPLAYしません。
通常Shazam検索そのもの、Rekordbox検索、補完該当なし／失敗時の通常再生は従来どおりです。

## 同曲判定・レーン

表示用曲名の先頭4文字一致による重複抑制は維持します。
これと認識確定の2回一致は別で、異なる既知Shazam IDの1回ずつを同一曲の2回一致には数えません。
先頭4文字が同じ別曲も重複扱いになる仕様です。

新規の既定は6レーンで、4～16の範囲で設定できます。
認識の投入間隔は3秒で、レーン数を増やしても間隔は変わりません。
全レーンが使用中なら空きを待ち、復帰後に追いつくための連続投入はしません。

## 手動操作

手動検索・手動PLAY・自動再生OFFを優先する動作は維持します。
アニメOPモードは、検索上位4件のうち90～105秒の動画を優先し、該当がなければ1位を使う既存仕様です。
