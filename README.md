# VJ_yattaro - Shazam.com + WebView2 統合版

メイン画面の操作感を維持しつつ、ShazamIOによる認識をShazam公式ページ＋WebView2に置き換えたソース一式です。

**Windows上のビルドと実際の楽曲認識は、この作業環境では未検証です。**
実行済みのテストと未確認の範囲は [VERIFICATION.md](VERIFICATION.md) に記載しています。

## v1.2.7 route-only日本語メタデータ補完

- Shazamが `/song/<id>/<romanized-slug>` だけ返し、曲名/アーティストが空でもApple DB連携を継続します。
- Shazam route IDをApple Track IDとして無条件採用はしません。
- まずroute IDをApple Lookupで候補化し、直接タイトル照合できない場合はローマ字route titleでApple Searchを実行します。
- Apple Searchの上位結果に同じTrack IDが再出現した場合だけ同一曲と確定し、そのIDのJPメタデータから日本語曲名とアーティストを採用します。
- 例: `14 Heibei Ni Souvenir Original Karaoke` / artist空欄 → `14平米にスーベニア (オリジナル・カラオケ)` + Apple JPのアーティスト。
- YouTubeのモード別検索テンプレートや検索順位には変更を加えていません。

## v1.2.6 モード別YouTube検索テンプレート

- 設定 > YouTube に `Rekordbox検索テンプレート` と `Shazam検索テンプレート` を個別追加。
- Rekordbox既定値は従来どおり `%tracktitle% %comment%`。既存の単一テンプレート設定はRekordbox側へ自動移行します。
- Shazam既定値は `%tracktitle% %artist%`（曲名 + アーティスト名）。
- 検索キューには検索開始時の入力モードも保持し、検索待ち中にRekordbox/Shazamを切り替えても別モードのテンプレートを誤適用しません。
- `%tracktitle%` / `%artist%` / `%comment%` は両方のテンプレートで引き続き使用できます。

## v1.2.5 Shazam UIラベル誤認識修正

- `Shazam フッター` / `Shazam Footer` / header / navigation 等を曲名候補から除外
- footer / contentinfo / navigation / header 配下のDOM見出しを認識候補から除外
- JS・C#・Pythonの3段階で同じガードを適用
- UIラベルを除外した後も、認識ルートslugとartistは保持し、`Modular Theorem / Metizone` のような実曲情報へフォールバック

## v1.2.4 約15秒応答を狙う2レーン認識

- Shazam WebView2 helperを2系統（lane 1 / lane 2）常駐させ、**4秒ずらして並列認識**します。
- 各helperは別WebView2プロファイルを使うため、同一User Data Folderのロックを競合しません。
- 片方が15秒のno-match待ちに入っていても、もう片方は新しい6秒録音で認識を進めます。
- 安全タイムアウトは18秒から15秒へ短縮しました。
- 2レーンの結果には連番を付け、古い録音の結果が新しい曲を後から上書きすることを防ぎます。
- Apple/iTunes日本語化ロジックは共通キャッシュを使い、同時結果による重複検索を抑えます。

今回の実ログでは1回の成功認識は約5.6〜13.8秒でした。v1.2.4はShazam自体を高速化するのではなく、
**「18秒失敗してから次の14秒認識を開始する」直列待ちをなくす**ことで、曲変更後の反映を15秒前後へ近づける設計です。
公式Shazam Web側の応答時間やネットワーク状態により15秒を保証するものではありません。

## v1.2.3 latency improvements

- Recognition readiness polling is 100 ms instead of 3 seconds, so the first request starts as soon as the configured microphone snapshot is full.
- The WebView2 host observes the official Shazam `/tag/` response generated by the webpage itself. This is observation only; it does not issue a second/private Shazam recognition request.
- Visible Shazam no-match messages are detected immediately instead of relying only on the 18 second safety deadline.
- A completed result is sent to Python only after the helper has finished cleanup and cleared its busy flag, eliminating the `helper is not ready or is busy` restart race.
- A homepage that is already ready is reused on retry instead of forcing another navigation.
- Apple EN identity and JP localization lookups/searches run in parallel where safe.
- Exact Apple identity can finalize after a short 250 ms grace; response-only text without Apple identity keeps a 650 ms grace so a Japanese Shazam route can still win.

The 15 second per-lane deadline remains a safety fallback. Successful recognition latency is still primarily controlled by the official Shazam website.

## ビルド

Windowsで **Python 3.12 / 64-bit** を使用します。元のアプリと別のフォルダに展開し、そのフォルダで実行してください。

```powershell
.\build.cmd
```

`.venv` の作成、Python依存関係の取得、.NETヘルパーのビルド、PyInstallerによるパッケージ化を行います。
.NET SDKは既存のものを使用し、なければMicrosoft公式スクリプトでユーザー領域へ導入します。
以前の `%LOCALAPPDATA%\ShazamWatch\dotnet-sdk-8` も検出対象です。
初回はインターネット接続が必要です。

## 起動

```powershell
.\dist\VJ_yattaro\VJ_yattaro.exe
```

いつもと同じ画面でShazamモードに切り替えます。
認識用ブラウザは通常非表示です。
別のPCへ配布する場合は、`dist\VJ_yattaro` を **フォルダごと** 渡してください。
実行先に **Microsoft Edge WebView2 Runtime** が必要です。
.NET Runtimeの別途導入は不要な構成でビルドします。

## 変更していないもの

`main.py`、`ui/`、`web/` の画面ファイルは元と同一です。
マイク選択、録音時間（5～20秒）、言語・国の設定、履歴の表示、YouTube検索への受け渡しは既存の仕組みを使います。
`shazam_history.json` の形式と最大50件の保存も維持しています。
既存の出力先にある `config.json` と `shazam_history.json` はビルド時に上書きしません。

## 内部処理の違い

既存の録音を、スピーカーに出さず内部のMediaStreamとしてShazam公式ページへ渡します。
公式ページが認識を行う間だけ、その録音区間を内部反復します。
マイクをWebView2側で別に開くことはしません。
認識は **2つの独立WebView2レーンを4秒ずらして並列** に実行します。各レーン内は1回ずつ直列ですが、
一方のno-match待ち中にももう一方へ最新録音を送れます。画面内の既存説明にある3秒はUI文言として残していますが、
内部の録音準備監視は100msです。

日本語メタデータはApple/iTunes DBとの連携を維持します。ただし**別曲を採用しないことを最優先**し、
Appleタイトルを採用するのは次のどちらかだけです。

1. Shazamの今回の結果に実際に出たApple MusicリンクのTrack IDをLookupできた場合
2. Apple Searchで **曲名とアーティストの両方が正規化後に完全一致**した場合

Shazamの `/song/<id>` / `/track/<id>` の数字はApple Track IDとして決め打ちしません。ただしライブ結果が
route-onlyだった場合だけ、その数値IDをApple Lookupへ「候補」として照会し、Apple英語タイトルがShazamの
URLスラッグと一致した場合に限って同一IDと確定し、同じIDのJPメタデータを採用します。認識ルートへ遷移した直後は
最大約1.8秒だけライブ結果から曲名・アーティスト・実Apple Musicリンクを取得します。`/ja-jp` のライブ結果で
日本語タイトルがすでに取得できている場合、Apple照合が安全に成立しなかったとしても、その日本語タイトルを
ローマ字のURLスラッグで上書きしません。静的Shazamページの別曲メタデータもルートIDとタイトル整合を確認して拒否します。

## ログとデバッグ

ログは既存と同じく、EXEの隣の `vj_yattaro.log` です。
以前のShazamWatchの `app.log` ではありません。
画面を確認する場合だけ、アプリを終了してから次のように起動します。

```powershell
$env:VJ_SHAZAM_DEBUG = "1"
.\dist\VJ_yattaro\VJ_yattaro.exe
```

サイトに同意画面が出た場合は、この画面で手動で確認してください。
アプリが利用者に代わって同意する処理は入れていません。
通常起動に戻すときは `Remove-Item Env:VJ_SHAZAM_DEBUG` を実行してから再起動します。

## 制約

認識するのはShazam公式ページですが、この組込み自体はApple公式Windows SDKではありません。
サイト仕様の変更やサービス側の制限に影響されます。
認識精度が公式スマホアプリと同一となることまでは検証していません。
詳細は [docs/INTEGRATION.md](docs/INTEGRATION.md)、変更ファイル一覧は `CHANGE_MANIFEST.json` を参照してください。

## v1.2 日本語Apple-safe統合

単体テスト版 v0.5.5 の方針を統合版へ移植しました。Shazamライブ日本語タイトルをApple照合の第一キーにし、

Shazamの結果領域にある「概要 / Overview」などのUIタブ名を曲名として採用しません。実Apple Music Track IDで同一曲を確認できた場合はApple DBの曲名を優先し、日本語Shazamタイトルを残すのはUIラベルではない実曲名に限ります。


## v1.2.2 Fast retry + route-ID Apple proof

実ログで、36秒のno-match待ちと、`/song/1655784202/inochi-moyashite-koiseyo-otome-game-version` の
route-only結果から日本語タイトルへ到達できないケースを確認しました。本版ではWebView2をShazamモード開始直後に
先行起動し、録音バッファが溜まる時間とブラウザ初期化を重ねます。Shazam認識レスポンスが明示的なno-matchを
返した場合は即終了して次の最新録音へ進み、最終安全タイムアウトも36秒から18秒へ短縮しました。

route-only時はShazamルートIDをApple IDと仮定せず候補照会し、Apple ENタイトルとShazam URLスラッグが一致した
場合だけ同一曲と確定してApple JPタイトル/アーティストを採用します。一致しなければApple候補を破棄します。
route-only時の低信頼なShazam公開HTML再取得も省き、不要な待ちを減らしています。
