# VJ_yattaro

RekordboxまたはShazamの検出結果からYouTube動画を検索・再生するWindowsアプリです。
このリポジトリにはソース、必要な画像、ビルド手順、回帰テストのみを収録しています。
ビルド済みEXE/DLL、個人設定、認識履歴、ログは含みません。

## ビルドと起動

Windows / Python 3.12（64-bit）/ Microsoft Edge WebView2 Runtimeを使用します。

```powershell
.\build.cmd
.\dist\VJ_yattaro\VJ_yattaro.exe
```

`build.cmd`は`.venv`の準備、Python依存関係の導入、.NETヘルパーの生成、
PyInstallerによるEXE作成を行います。.NET SDK 8以降を探し、見つからなければ
既存のビルドスクリプトがユーザー領域へ.NET 8 SDKを導入します。
初回の依存関係取得にはインターネット接続が必要です。

Python依存関係が導入済みの場合は、次のコマンドで再ビルドできます。

```powershell
.\build.cmd -SkipInstall
```

ソースから起動する場合も、先にPython依存関係とネイティブヘルパーを準備してください。
一度通常のビルドを済ませた環境では次のように起動できます。

```powershell
.\native\ShazamWebViewBridge\build.cmd
.\.venv\Scripts\python.exe main.py
```

配布するのは`dist\VJ_yattaro`フォルダー全体です。EXEだけでは動作しません。
配布先にもWebView2 Runtimeが必要です。.NETヘルパーは自己完結型で生成します。

## Shazamの4レーン認識と同曲判定

Shazamモードは**4本の独立WebView2レーンを共有ワーカープール**として使います。

- 全体では新しい認識開始を**3秒以上**ずらします。
- あるレーンがbusyでも、別の空きレーンがあればそのレーンへ次の認識を投入します。
- 4レーンすべてがbusyの場合、その認識スロットを捨てません。最初にレーンが空いた時点で最新の録音スナップショットを作って即時投入します。
- busy待ちから復帰した後は、追いつくための連続投入を行わず、実際に投入した時刻から次の3秒を数えます。
- そのためShazam応答が12秒を少し超えても、旧固定レーン方式のように各レーンの次の12秒周期を丸ごと失いにくくなっています。

誤検出対策は、同じ録音を複数回投げるのではなく、**時間の異なる2回の認識結果**で行います。

- 1回目の新しい曲は`Candidate pending`として内部保留し、履歴追加・YouTube検索・動画切替を行いません。
- 次の有効な認識でも同一曲と判定された場合だけ`Temporal confirmation`となり、初めて確定します。
- `no-match`が入った場合は連続確認をリセットします。
- 認識完了順が前後しても、要求連番`seq`順に処理します。

同一曲判定は従来どおり`track_matching.py`の`is_same_track()`を使います。

- **曲名の先頭4文字が一致すれば、アーティスト名が異なっても同じ曲**として扱います。両方の曲名が4文字以上であることが条件です。
- 前後の空白と英字の大文字・小文字は無視します。途中の空白や記号はそのまま比較します。
- この条件に該当しない場合は、従来の「曲名・アーティスト名の先頭6文字を使った部分一致」と、アーティスト未取得時の判定を維持します。

例えば`炉心融解 (feat. 鏡音リン)`と`炉心融解(カバー)feat. リツカ`は同じ曲です。
連続して同曲と判定した場合、履歴の追加・保存、新曲通知、YouTubeの自動再検索はしません。

Shazamのoffsetは今回の確定判定には使用しません。実機ログでoffsetが取得できないケースでも2回連続確認だけで誤検出抑止が機能しているため、判定経路を単純化しています。

## YouTube検索が0件の場合

設定済みの検索テンプレートでまず検索し、表示できる動画が0件の場合だけ再検索します。
標準のShazam検索では、次の順で最大3種類の検索語を試します。

1. 元の曲名とアーティスト名。
2. 元の曲名のみ。
3. `(loves. ...)`、`(feat. ...)`、`(featuring ...)`、`(ft. ...)`の付加情報を除いた曲名。

結果が出た時点で終了し、通常時は追加検索しません。重複する検索語も省きます。
アーティスト名だけへの再検索は行いません。通信・APIエラーは0件とは区別します。
従来の60秒未満の動画を除外する処理で全件が消えた場合も、次の検索語へ進みます。

手入力でも、`曲名 (loves. 歌手) アーティスト`のように区切りが明確な場合は対応します。
任意の検索文から最後の単語を機械的に削除する処理は行いません。
通常の`(Live)`や`(Remix)`などは残し、固定のテンプレート文字とコメントも維持します。
曲名を使わないカスタムテンプレートに、曲名検索を勝手に追加しません。
表示用の曲名と保存履歴は書き換えません。

検索語、APIの返却件数、動画除外後の件数をログで確認できます。
再検索でも実際のヒットや正しい曲の一位表示を保証するものではありません。

## アニメOPモード

タイトルバーの「自動再生」の右隣に「アニメOPモード」ボタンを追加しました。

| 自動再生 | アニメOPモード | 動作 |
|---|---|---|
| OFF | OFF固定（操作不可） | 自動再生しない |
| ON | OFF | 従来どおり検索結果1位を再生 |
| ON | ON | 上位4件にある1:30〜1:45の動画を優先再生 |

判定するのは**動画全体の長さ**です。1:30と1:45も対象に含みます。
表示される検索結果の上位4件だけを確認し、複数該当する場合は検索順位が最も高い動画を選びます。
該当なしの場合は1位を再生します。5位以下や長さが不明の動画は優先対象にしません。
動画の内容がアニメOPかどうかを判別する機能ではありません。

検索結果の並びは変えず、自動再生する動画に選択表示を合わせます。
既存の長さ情報を使うため、このモードによる追加のAPI通信はありません。
手入力などの手動検索では、両方がONでも自動再生しません。
ボタンの切替だけで現在の動画を切り替えず、次の自動検索結果から適用します。

初期値はOFFで、設定は`config.json`の`anime_op_mode`に保存します。
自動再生をOFFにすると、モードの保存値もOFFに戻します。
自動再生をONに戻しただけではモードは復活しません。

## Gitへの配置

ZIPの直下がリポジトリのルートです。余分な親フォルダーはありません。

`bin/`、`obj/`、`publish/`、`build/`、`dist/`、Pythonキャッシュ、仮想環境、
`config.json`、`shazam_history.json`、ログ等は`.gitignore`で除外します。
APIキーは個人用の`config.json`で管理し、ソースへ書き込まないでください。

**既存フォルダーへの上書き展開だけでは、ZIPに含まれない旧ファイルは削除されません。**
また、`.gitignore`はすでにGitで追跡しているファイルを追跡解除しません。
既存リポジトリへ反映する際は、`.git`と必要な個人データを保護し、
旧ビルド生成物や廃止した文書が残っていないか確認してください。
`build.cmd`は既存の配布先の設定・履歴を維持します。

## 構成

| パス | 役割 |
|---|---|
| `main.py`, `ui/` | デスクトップ画面と操作 |
| `app/services/` | 認識、履歴、YouTube検索、設定、外部連携 |
| `app/services/track_matching.py` | Qtや通信に依存しない同曲判定 |
| `app/services/autoplay_selection.py` | 長さと順位による自動選曲（Qt・通信不要） |
| `web/` | 動画プレイヤー |
| `native/ShazamWebViewBridge/` | WebView2ヘルパーのソース |
| `tools/`, `VJ_yattaro.spec` | ビルドと配布物の検査 |
| `tests/` | オフライン回帰テスト |

前回の同曲判定・検索フォールバック・ファイル整理を維持しています。
アニメOPモードの実装変更は`main.py`と設定の初期値、新規の選曲関数です。
タイトルバーは`main.py`内にあります。`ui/`と`web/`のファイルは変更していません。
今回の4レーン化は`app/services/shazam_service.py`が中心で、ネイティブヘルパーの通信方式、
ビルド手順、依存関係、履歴JSONの形式は変更していません。

## テストと調査用起動

実行コマンドと確認範囲は[テスト手順](docs/TESTING.md)、
内部構成は[Shazam連携](docs/INTEGRATION.md)を参照してください。
WindowsでのEXEビルド、実マイク、実際のShazam認識は今回の作業環境では未検証です。

ログは通常`vj_yattaro.log`です。認識画面を表示して調査する場合だけ、
アプリを終了した状態で次を実行します。

```powershell
$env:VJ_SHAZAM_DEBUG = "1"
.\dist\VJ_yattaro\VJ_yattaro.exe
```

通常起動へ戻す際は、アプリを終了して`Remove-Item Env:VJ_SHAZAM_DEBUG`を実行します。
サイトの同意画面が出た場合は利用者が手動で操作してください。
